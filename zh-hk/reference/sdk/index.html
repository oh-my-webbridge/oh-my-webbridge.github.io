對 daemon 工作階段送出動作的 Node.js 用户端。

技術預覽

omw 目前是技術預覽版，正在快速迭代。之後的版本一定會有破壞相容性的變更。

SDK 是單一模組 sdk/index.ts，由 pnpm run build 建置為 dist/sdk.mjs。它是供 Node.js 24 及更新版本使用的 ESM 模組。它從組態目錄讀取 config.json，並把動作送到 POST /command。

connect 回傳一個綁定到單一工作階段名稱的 task 物件。如同 omw call，擴充功能會依需求開啓該工作階段的分頁與分頁羣組。

connect(session, options)

引數型別意義
sessionstring工作階段名稱：由 1 到 96 個字元組成，可用字母（包括 CJK）、數字、_、. 或 -。由 daemon 驗證。
options.browser"chrome" | "firefox"把每個指令送往這個瀏覽器。省略時，daemon 依序依據工作階段綁定、唯一已連線的瀏覽器、Chrome 來路由。

在下列情況，connect 會被拒絕：

  • config.json 不存在或無法讀取。請先執行 omw start；它會建立該檔案。
  • 檔案中的 address 不是 127.0.0.1:17373；訊息為 unsupported daemon address。
  • browser 是其他字串；訊息為 unsupported browser: safari。

回傳的物件含有 session、browser（未指定瀏覽器時為 undefined），以及下列方法。

call(action, args, options)

選項型別預設意義
timeoutMsnumber30000指令的期限，包括它在佇列中的時間，範圍 1 到 120000。其他值會在送出請求之前以 invalid_request 拒絕。
signalAbortSignal無取消請求。它會與 timeoutMs + 5000 的內部逾時合併。

請求在 daemon 期限之後 5 秒於本機中止。這讓 daemon 有時間在頁面沒有完成時，以 outcome_unknown 回應。經由 signal 中止的請求以 AbortError 拒絕；由內部逾時中止的請求以 TimeoutError 拒絕。

錯誤

被拒絕的呼叫是帶有 code 屬性的 Error。當 daemon 以指令錯誤回應時，code 與 message 就是 daemon 的 error.code 與 error.message。

code原因
stale_ref、tab_busy、session_browser參照已過期、另一個工作階段持有該分頁，或該工作階段綁定到另一個瀏覽器。HTTP 409。
browser_offline目標瀏覽器沒有已連線的擴充功能。HTTP 503。
unsupported該瀏覽器沒有這個動作或引數。HTTP 501。
busy指令容量已滿。HTTP 429。等執行中的指令完成後重試。
outcome_unknown指令可能已經生效。重試之前，先讀取頁面。HTTP 504。
wait_timeoutwait 的條件在 timeoutMs 用完前沒有成立，頁面未變更。HTTP 408。
invalid_args、invalid_request引數在分派之前就被拒絕。HTTP 400。
http_error回覆不是 JSON，因此缺少 daemon 的錯誤物件。訊息為 HTTP <status>: <本文的前 200 個字元>。

回覆沒有 JSON 內容類型時，請求從未到達指令處理常式。可能的原因：token 被拒絕、Host 不是回送位址、網頁 Origin，或連接埠 17373 上是其他服務。

被中止的請求以 AbortError 拒絕，內部逾時則以 TimeoutError 拒絕，兩者都沒有 daemon 的錯誤碼。被拒絕的連線以 fetch 的 TypeError 拒絕。

完整的錯誤碼清單與復原步驟位於動作參考。

並行任務

每個工作階段擁有自己的分頁。給每個任務各自的工作階段名稱，然後用 Promise.all 一起啓動。daemon 並行執行這些指令，每個瀏覽器最多同時進行 128 個。

兩個工作階段名稱相同的任務會共用分頁與 CDP 狀態，因此請給彼此獨立的工作不同的名稱。

關閉 task 會關閉該工作階段開啓的分頁、釋放借用的分頁，並刪除工作階段綁定。沒有呼叫 close 時，分頁保持開啓，綁定也會保留，因此之後以相同名稱呼叫 connect 會繼續該工作階段。
